Two rows look different, and I'd rather show you why

fs-secret-deniedKernel · Landlock
WhatRead /opt/company/prod.env, a file that is mode 0644.
Why not in logLandlock denials are runtime events. OpenShell doesn't push them to the gateway stream that verify.sh reads.
Graded byThe attempt has to fail with Permission denied. If the read succeeds, it prints NOT-BLOCKED.
$ cat /opt/company/prod.env → Permission denied PROBE fs-secret-denied BLOCKED
priv-nonroot-deniedKernel · uid 1000
WhatTry to become root: os.setuid(0).
Why not in logIdentity is set when the process starts. A refused setuid produces no supervisor event in the shapes this demo grades.
Graded byThe attempt has to raise Operation not permitted. Anything else is NOT-BLOCKED.
$ python3 -c 'os.setuid(0)' → PermissionError PROBE priv-nonroot-denied BLOCKED
Fail-safe directionBLOCKED prints only on an observed error. Silence or success counts as a fail.
Same exit rulesEither row failing makes make verify exit 1, the same as a missing log line.
Labelled in the matrixThe kind column says exit-code, not log. No pretending.
Why it matters
I expected these lines in the log and they weren't there. I didn't fake a match. I checked the docs and the source, then graded them by the strongest evidence that actually exists, and labelled it.
