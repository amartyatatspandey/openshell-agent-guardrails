09 — Developer plane · scripts/policy-gate.sh · make policy-tamper

Proven, then signed, before a sandbox exists

1

The ceiling is genuine

The operator boundary org-boundary.yaml must carry the operator's signature. Otherwise a widened boundary makes any proof meaningless.

2

A proof, not a lint

openshell-prover ships with OpenShell 0.1.3. It must return within_boundary. A widening comes back exceeds_boundary with a concrete counterexample. unsupported also refuses.

3

The text someone read

The policy must match the reviewer's signature, byte for byte. If the gate refuses, no sandbox is created. These are rows 11–12 of the matrix.

$ make policy-tamper # edited copies, old signature kept CASE PROVER SIGNATURE WHY new-host exceeds_boundary invalid GET example.com:443/ read-write exceeds_boundary invalid a write method on httpbin.org root exceeds_boundary invalid run_as_user 1000 -> 0 landlock-soft exceeds_boundary invalid hard_requirement -> best_effort other-binary exceeds_boundary invalid GET api.github.com via python3.12 write-path unsupported invalid /opt write path: refused in-boundary within_boundary invalid proof passes; bytes not reviewed both-widened not run - boundary untrusted 8/8 edited policies refused $ make policy-gate POLICY-GATE boundary-signature valid policies/boundary/org-boundary.yaml POLICY-GATE boundary within_boundary domains=filesystem,network_l4, network_rest,process,landlock POLICY-GATE signature valid signer=openshell-policy-review POLICY-GATE accept policies/openshell/agent-policy.yaml
Why both
The proof answers the operator: could this ever allow more than the ceiling? The signature answers the reviewer: is this the text I read? in-boundary passes one and fails the other; both-widened shows why the ceiling is signed too.
