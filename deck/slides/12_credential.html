12 — The credential idea · the most AIControls-shaped control

The agent can hold a credential and still can't leak it

Bound endpoint · allowed
Sandbox envGITHUB_TOKEN=openshell:resolve:env:… a placeholder, not the value
Agentcurl GET to api.github.com:443
SupervisorHost, port and path match the demo-github profile, so the real value is swapped in at the proxy
ResultRequest goes out. The secret was never inside the sandbox.
Any other endpoint · denied
AgentSends the same placeholder to httpbin.org, a host the network policy allows
SupervisorNot the endpoint the credential is bound to, so it refuses to resolve it
OpenShell logHTTP:GET DENIED engine:credential-binding plus a FINDING:BLOCKED [HIGH]
ResultNothing leaves with the credential. Two rows PASS.
HTTP:GET [HIGH] DENIED GET [policy:public_echo engine:credential-binding] [reason:credential_endpoint_mismatch] FINDING:BLOCKED [HIGH] "Provider credential used at an unauthorized endpoint" [type:openshell.provider_credential.endpoint_mismatch]
Network allow ≠ credential allowhttpbin.org is reachable, but the credential still won't resolve there.
Structural, not policedLeaking it isn't detected afterwards. It can't happen.
Fleet relevanceExactly the leaked-token incident class AIControls governs on the MCP plane.
