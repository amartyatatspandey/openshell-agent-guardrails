MCP firewall: per tool, per argument

OpenShell decides where

Only POST /mcp on that host

The fake MCP server is reached as host.openshell.internal. L7 rules admit POST /mcp and nothing else, so POST /admin is an engine:l7 denial.

Kyverno decides what

CEL reads the JSON-RPC body

Tool allowlist [search_issues, read_file]. Flag-shaped arguments and .. or absolute paths are denied. The server advertises delete_repo; it still can't be called.

Fail-closed

No decision means no

A body Kyverno can't parse errors out, and on_error: fail_closed denies it. Every denial happens before credentials, and the server never sees it.

Found by testing kyverno-authz v0.4.0

  • An allow from one policy decided the request. The GitHub rule's Allowed() overrode the MCP rule's deny. Fixed with matchConditions per policy.
  • A policy that fails to compile allows everything, silently. mcp.Parse doesn't exist in v0.4.0, and the docs' v1 needs to be v1alpha1. So make kyverno proves both rules deny before it touches the gateway.
  • The proof still applies. The policy gate proves this policy too, with the middleware stripped, since middleware can only narrow.
